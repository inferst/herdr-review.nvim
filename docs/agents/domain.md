# Domain Docs

This repository uses a single-context domain documentation layout.

## Before exploring

Read `CONTEXT.md` at the repository root and relevant ADRs under `docs/adr/`
when they exist. If they do not exist, proceed silently. Domain documentation
is created only when terminology or an architectural decision needs to be
recorded.

## Vocabulary

Use terms defined in `CONTEXT.md` in issue titles, implementation plans, tests,
and documentation. If a needed concept is absent, reconsider the terminology
or record the gap for domain modeling.

Surface any proposal that contradicts an existing ADR instead of silently
overriding it.
